# Data Dictionary

Synthetic operational dataset for MacroOps AI. Period: 1 Sep 2026 to 30 Sep 2026. 100 stores. Generated by `src/generate_data.py` (seed 42).

## Tables

| Table | Rows | Grain |
|---|---|---|
| orders | 100,000 | one row per order |
| picking | 25,000 | one row per picked order (subset of delivered orders) |
| delivery | 25,000 | one row per delivered order (same orders as picking) |
| inventory | 40,000 | one row per store x SKU (400 SKUs per store) |
| workforce | 10,000 | one row per employee (no date, store-level snapshot) |

## Relationships

```
orders.order_id  -> picking.order_id      (25% of orders have picking detail)
orders.order_id  -> delivery.order_id     (same 25%)
orders.store_id  -> inventory.store_id    (store level only, no order-SKU link)
orders.store_id  -> workforce.store_id    (store level only, no date)
inventory.sku_id identifies products
picker_id / rider_id identify operational resources
```

## orders

| Column | Type | Meaning |
|---|---|---|
| order_id | str | `ORD-000001` ... |
| store_id | str | `ST001` ... `ST100` |
| order_time | datetime | when customer placed order |
| item_count | int | items in basket (1-15) |
| order_value | float | basket value |
| promised_time | datetime | SLA promise shown to customer. Based on items and distance only |
| actual_delivery_time | datetime | delivery time. **Empty for Cancelled / Failed** |
| status | str | `Delivered_On_Time`, `Delivered_Late`, `Cancelled`, `Failed` |
| sla_breached | int | 1 if actual_delivery_time > promised_time, else 0. Always 0 for Cancelled / Failed |
| delivery_delay_minutes | float | minutes late (0 if on time or not delivered) |

## picking

| Column | Meaning |
|---|---|
| order_id, picker_id | order and picker (`PICK00001` ...) |
| pick_start, pick_end | picking window |
| items_picked | item_count minus items_missing |
| items_missing | items not found on shelf (stockout or phantom stock) |
| pick_duration_minutes | pick_end minus pick_start |

## delivery

| Column | Meaning |
|---|---|
| order_id, rider_id | order and rider (`RID00001` ...) |
| assignment_time | when a rider was assigned |
| pickup_time | rider collected the order at store |
| delivery_time | handed to customer. Equals orders.actual_delivery_time |
| distance_km | store to customer distance |
| assignment_delay_minutes | wait between pick_end and rider assignment |

Order timeline (100% consistent in v2):
`order_time -> pick_start -> pick_end -> assignment_time -> pickup_time -> delivery_time`

## inventory

| Column | Meaning |
|---|---|
| store_id, sku_id | store and product |
| system_stock | stock in system |
| physical_stock | stock on shelf |
| stockout | `Yes` if physical_stock = 0 |
| stock_variance | physical minus system |
| inventory_accuracy_pct | min(physical, system) / system x 100, capped at 100 |

Phantom stock: system_stock > 0 while physical_stock = 0. These cause missing items at picking.

## workforce

| Column | Meaning |
|---|---|
| employee_id | `EMP00001` ... |
| role | Picker, Packer, Store Associate, Rider Coordinator, Supervisor |
| store_id | home store |
| shift | Morning, Afternoon, Evening, Night |
| tasks_completed, tasks_pending | task counts. Pending ratio is a stress signal |

Workforce has no date column. It can only be used as store-level features (headcount, pending ratio), not matched to a specific order time.

## master table (`data/processed/master.parquet`)

34 columns, 100,000 rows, built by `src/build_master.py`. One row per order.

| Group | Columns |
|---|---|
| orders (10) | as above |
| derived time features (6) | promised_minutes, total_minutes, order_date, hour, dow, is_weekend |
| picking (6) | picker_id, pick_start, pick_end, items_picked, items_missing, pick_duration_minutes |
| delivery (5) | rider_id, assignment_time, pickup_time, distance_km, assignment_delay_minutes |
| store inventory aggregates (3) | stockout_rate, avg_inv_accuracy, avg_abs_variance |
| store workforce aggregates (2) | headcount, pending_ratio |
| flags (2) | has_ops_detail (has picking/delivery rows), is_delivered (status is Delivered_*) |

## Columns to exclude from SLA-risk model features (leakage)

`status`, `sla_breached`, `delivery_delay_minutes`, `actual_delivery_time`, `total_minutes`, `pickup_time` (after assignment stage), `delivery_time`.

Features are grouped by the stage at which they become known:

| Stage | Known at | Features |
|---|---|---|
| 1 | order placed | item_count, order_value, promised_minutes, hour, dow, distance_km, store stockout_rate, headcount, pending_ratio |
| 2 | picking done | + pick_duration_minutes, items_missing |
| 3 | rider assigned | + assignment_delay_minutes |
